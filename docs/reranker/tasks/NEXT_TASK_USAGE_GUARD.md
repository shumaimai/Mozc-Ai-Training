# 次タスク指示: 実使用ガード＋実ログ評価＋（次段）再学習

対象: リポジトリ作業エージェント
前提: `docs/reranker/reports/PHASE3_CTX_REPORT.md` / 実使用ログ `artifacts/rerank_ctx/eval/ime_usage_pairs.jsonl`（186件）

## 背景（実ログが示した問題）

実使用でリランカーが**net −8pt**（shown==wanted 72% vs Mozc単体 80%）。上書き37回中 **助けた6 / 壊した21**。
失敗モード: **短い読み・数字/記号だけの文脈・ありふれた語**で、**珍字/旧字（讃仰・狭義・灸・旧・實際）を高margin(3〜5)で過剰昇格**。τ=2.5では止まらない。原因は**評価(Wikipedia)と実使用の分布ズレ**。

方針: ①即効ガードで実害を止める → ②実ログを主評価にする → ③実使用寄りに再学習。**その間は既定OFF維持。**

---

## タスク1: 即効ガード（推論側・再学習不要）

リランカーが**触ってよい所だけ触る**。以下のいずれかに当たる変換は**リランクせず Mozc 順を返す**（`RerankRewriter` とオフライン hook/デーモンの両方に同一実装で入れる）:

1. **rerank 対象読みのホワイトリスト方式（本命）**: `reading_gold_map.json` から **context_sensitive な読み**（`top_gold_share < 0.7` かつ 漢字gold≥2 かつ `gold≠reading`、機能語POS除外）を抽出し、**その集合に入る読みだけリランク**。それ以外は Mozc 順。これで短読み・高頻度一強・機能語が自動で外れる。
2. **補助ヒューリスティック**（ホワイトリストの穴埋め）:
   - **読み長 ≤ 2**（い/きゅう/ねん/がつ/にち）→ リランクしない
   - **文脈が空 or 数字・記号のみ** → リランクしない
   - 候補が旧字体/半角カナのみ等の明らかなゴミは対象外

出力: `artifacts/rerank/rerank_eligible_readings.json`（ホワイトリスト）＋ガードのユニットテスト。

## タスク2: 実ログ評価ハーネス（主評価に昇格）

`ime_usage_pairs.jsonl` を**リプレイ**して、ガード有無での純効果を測る:
- 指標: `shown==wanted` 率、Mozc単体比の純pt、上書きの 助けた/壊した 件数。
- ガード適用後、**net が Mozc 以上（≥ +0pt、目標 プラス）**になることを確認。
- 出力: `artifacts/rerank_ctx/eval/usage_replay_report.json`。
- 以後、Wikipedia holdout だけでなく**このログを主評価**として併記する。

## タスク3（次段）: 実使用寄りの再学習

ガードで止血できたら、根本修正:
- 学習に **「上書きするな」アンカーを大量追加**: ありふれた語（産業/競技/級/実際…）、短い読み、数字/記号文脈を Mozc-top1=正解として。
- **旧字体・珍字の昇格にペナルティ**（正例を新字体に寄せる／旧字を負例に）。
- **評価は `ime_usage_pairs.jsonl` を含める**（Wikipediaだけで測らない）。
- Track B レシピ（30m, ctx, τ再スイープ）で再学習 → 実ログ net がプラスで安定するまで。

## タスク4: もっさり対策（軽く・同時に）

- ガード①で**モデル呼び出し回数が減る**＝遅延露出も減る（主効果）。
- デーモンの ORT が **intra=CPUコア数**か確認（intra=1 なら遅い）。**常駐で温まったまま**か（アイドル後の初回が冷えると"たまに"もっさり）を確認。
- p95 タイムアウト200ms超は fail-safe で Mozc 順に落ちる（設計通り）。必要ならタイムアウトを250msへ緩める判断。
